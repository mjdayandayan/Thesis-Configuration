## STEP 6: DEPLOYING THE AI MODEL AND TESTING EVERYTHING

> **What you'll do:** Download the AI model from Edge Impulse, copy it to the Pi, and then test each part of the system individually (soil sensor, camera, AI model). Finally, run the full system.

> **What you need for this step:**
> - VS Code connected to the Pi (from Step 5), or SSH access
> - The Pi with all hardware connected (from Step 3)
> - The 12V power supply turned on (for the soil sensor)
> - Your Edge Impulse account (to download the model)

---

### Part A: Download and Deploy the AI Model

> **What is the .eim file?** It's the AI model file trained on Edge Impulse (FOMO MobileNetV2 0.35 architecture), compiled specifically to run on the Raspberry Pi. The `.eim` stands for "Edge Impulse Model."

#### On your laptop:

1. **Go to your Edge Impulse project** in a web browser: https://studio.edgeimpulse.com/

2. **Click "Deployment"** in the left sidebar

3. **Search for** or select **"Linux (AARCH64)"**
   - AARCH64 is the processor type of the Raspberry Pi 5
   - ⚠️ Do NOT choose "Linux (x86)" — that's for regular PCs, not the Pi

4. Select **"Quantized (int8)"** — this is the optimized version for the Pi

5. Click **"Build"** and wait for it to compile

6. **Download** the `.eim` file (it will save to your Downloads folder)
   - The filename will be something like: `rice-growth-monitoring-c922-runner-linux-aarch64-ethos-v1-impulse-#1.eim`

#### Copy the model to the Pi:

7. **Open a terminal on your laptop** (not VS Code's terminal) and run:
   ```
   scp ~/Downloads/rice-growth-monitoring-c922-runner-linux-aarch64-ethos-v1-impulse-#1.eim pi@trio.local:~/thesis/models/
   ```

   > **On Windows**, the path might be:
   > ```
   > scp "C:\Users\YourName\Downloads\rice-growth-monitoring-c922-runner-linux-aarch64-ethos-v1-impulse-#1.eim" pi@trio.local:~/thesis/models/
   > ```

   Enter the password (`raspberrypi`) when prompted.

#### Make the model executable:

7. **SSH into the Pi** (or use VS Code's terminal):
   ```
   ssh pi@trio.local
   ```

9. **Make the model file executable:**
   ```
   chmod +x ~/thesis/models/rice-growth-monitoring-c922-runner-linux-aarch64-ethos-v1-impulse-#1.eim
   ```

   > **What does `chmod +x` do?** It gives the file "execute permission" — the system needs this to be able to run the model. Without it, you'll get a "Permission denied" error.

9. **Update the settings file** with the correct model filename:
   - Open `config/settings.py` in VS Code (or use `nano`):
     ```
     nano ~/thesis/config/settings.py
     ```
   - Find the line that says `MODEL_PATH` and verify it matches your model's filename:
     ```python
     MODEL_PATH = "/home/pi/thesis/models/rice-growth-monitoring-c922-runner-linux-aarch64-ethos-v1-impulse-#1.eim"
     ```
     > **Note:** This should already be set correctly in the repo. Only change it if you downloaded a differently named file.
   - Save and exit (in nano: press `Ctrl+O`, Enter, then `Ctrl+X`)

### Part D: Set Up Auto-Start on Boot (Optional)

> **What does this do?** Creates a "service" that automatically starts the monitoring system whenever the Pi boots up. This means you don't have to SSH in and manually start the program every time.

1. **Create the service file:**
   ```bash
   sudo tee /etc/systemd/system/thesis.service << 'EOF'
   [Unit]
   Description=Rice Paddy Monitoring System
   After=network-online.target
   Wants=network-online.target

   [Service]
   Type=simple
   User=pi
   WorkingDirectory=/home/pi/thesis
   Environment=PATH=/home/pi/thesis/venv/bin:/usr/bin:/usr/local/bin
   ExecStart=/home/pi/thesis/venv/bin/python /home/pi/thesis/src/main.py
   Restart=always
   RestartSec=10
   StandardOutput=journal
   StandardError=journal

   [Install]
   WantedBy=multi-user.target
   EOF
   ```

   > **What is a systemd service?** It's how Linux manages programs that run in the background. By creating a service, the Pi's operating system will start, stop, and restart our program automatically.

2. **Enable and start the service:**
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable thesis.service
   sudo systemctl start thesis.service
   ```

   > **What do these commands do?**
   > - `daemon-reload` = tells the system to read the new service file
   > - `enable` = tells the system to start the service on every boot
   > - `start` = starts the service right now

3. **Check if it's running:**
   ```bash
   sudo systemctl status thesis.service
   ```

   > **What you should see:** A green "active (running)" status.

4. **View live logs** (to see what the system is doing):
   ```bash
   journalctl -u thesis.service -f
   ```
   Press `Ctrl+C` to stop watching the logs.

5. **To stop the service** (e.g., for development/debugging):
   ```bash
   sudo systemctl stop thesis.service
   ```

### Part E: Retraining the AI Model Later

> **You don't need to do this now.** This is for after you've been running the system in the field and want to improve the AI model with real-world images.

The system automatically saves camera frames to `~/thesis/data/retraining_frames/`. When you're ready to retrain:

1. **Copy the saved frames to your laptop:**
   ```bash
   scp -r pi@trio.local:~/thesis/data/retraining_frames/ ~/Downloads/retraining_frames/
   ```

2. **Upload to Edge Impulse:** Go to **Data acquisition → Upload data** and upload the frames

3. **Label the new images** using Edge Impulse's labeling tool

4. **Retrain** with these recommended settings:
   - Model: FOMO (Faster Objects, More Objects) MobileNetV2 0.35
   - Input size: 320×320 RGB
   - Training cycles: 100 (increase to 200 if free-tier compute allows)
   - Learning rate: 0.005
   - Data augmentation: ON
   - Batch size: 32
   - Quantization: int8 (for deployment)

   > **Note:** The free Edge Impulse tier has a 1-hour compute limit. FOMO at 320×320 with 100 epochs fits within this. If you need more epochs, reduce image size to 160×160.

5. **Deploy the new model** (repeat Part A of this step):
   ```bash
   scp ~/Downloads/rice-growth-monitoring-c922-runner-linux-aarch64-ethos-v1-impulse-#1.eim pi@trio.local:~/thesis/models/
   ssh pi@trio.local "chmod +x ~/thesis/models/rice-growth-monitoring-c922-runner-linux-aarch64-ethos-v1-impulse-#1.eim"
   ```
   Update `MODEL_PATH` in `config/settings.py` if the filename changed, then restart:
   ```bash
   sudo systemctl restart thesis.service
   ```

### Part F: Setting Up the Web Dashboard (Supabase + Streamlit)

> **What does this do?** Sets up a web dashboard that displays live sensor readings, AI detections, camera images, and alerts — accessible from any browser. The RPi sends data to Supabase (a cloud database), and the Streamlit dashboard reads from it.

> **What you need for this step:**
> - A Supabase account (free): https://supabase.com
> - Python installed on your **laptop** (not the Pi)
> - The Pi connected to WiFi and running the monitoring system

---

#### Step 1: Create a Supabase Project

1. Go to https://supabase.com and sign in (or create a free account)
2. Click **"New Project"**
3. Fill in:
   - **Name:** `thesis`
   - **Database Password:** choose a strong password (save it somewhere)
   - **Region:** pick the closest to you
4. Click **"Create new project"** and wait for it to become **Healthy** (green dot)

#### Step 2: Create the Database Table

1. In Supabase, click **"SQL Editor"** in the left sidebar
2. Click **"New Query"**
3. Open the file `ui/supabase_setup.sql` from this repository and **copy-paste the entire contents** into the editor
4. Click **"Run"**
5. You should see `Success. No rows returned` — the `readings` table is now created

#### Step 3: Create the Image Storage Bucket

1. Click **"Storage"** in the left sidebar
2. Click **"New Bucket"**
3. Name: `field-images`
4. Toggle ON **"Public bucket"**
5. Click **"Create bucket"**
6. Go to **Storage → Policies** and add these policies under **"OTHER POLICIES UNDER STORAGE.OBJECTS"**:

| Policy Name | Allowed Operation | Policy Definition |
|---|---|---|
| `Allow public uploads` | **INSERT** | `true` |
| `Allow public reads` | **SELECT** | `true` |

> **If the UI gives errors**, run this in the SQL Editor instead:
> ```sql
> CREATE POLICY "Allow public reads" ON storage.objects FOR SELECT USING (true);
> CREATE POLICY "Allow public uploads" ON storage.objects FOR INSERT WITH CHECK (true);
> ```

#### Step 4: Get Your API Credentials

1. Go to **Project Settings** (gear icon, bottom of left sidebar) → **API**
2. Copy the **Project URL** (e.g., `https://xxxxx.supabase.co`)
3. Copy the **anon public** key (starts with `eyJ...`)

#### Step 5: Configure the RPi to Send Data to Supabase

1. Open `config/settings.py` on the Pi
2. Fill in the Supabase credentials:
   ```python
   SUPABASE_URL = "https://xxxxx.supabase.co"        # Your Project URL
   SUPABASE_KEY = "eyJhbGciOiJIUzI1NiIs..."           # Your anon public key
   SUPABASE_BUCKET = "field-images"                    # Leave as-is
   ```
3. Restart the monitoring service (if running):
   ```bash
   sudo systemctl restart thesis.service
   ```

#### Step 6: Configure and Run the Dashboard (On Your Laptop)

1. **Create the secrets file** — copy the example and fill in your credentials:
   ```
   cd ui/.streamlit
   cp secrets.toml.example secrets.toml
   ```
   Edit `secrets.toml` and paste the same Supabase URL and anon key:
   ```toml
   SUPABASE_URL = "https://xxxxx.supabase.co"
   SUPABASE_KEY = "eyJhbGciOiJIUzI1NiIs..."
   ```

   > ⚠️ **Do NOT commit `secrets.toml` to git!** It's already in `.gitignore`.

2. **Install dashboard dependencies** (one-time, on your laptop):
   ```
   cd ui
   pip install -r requirements.txt
   ```

3. **Run the dashboard:**
   ```
   streamlit run app.py
   ```

4. **Open in your browser:** visit `http://localhost:8501`

> **What you should see:**
> - If the Pi has sent data: live sensor metrics, AI detection results, and camera images
> - If no data yet: "No data received yet. Waiting for the Raspberry Pi to send its first reading..."
>
> To send a test reading, run on the Pi:
> ```bash
> cd ~/thesis && source venv/bin/activate
> python3 src/main.py --once
> ```
> Then click **"🔄 Refresh Data"** on the dashboard.

#### Step 7: Deploy to the Internet (Optional — Streamlit Cloud)

> **What does this do?** Makes your dashboard accessible from any device via a public URL (e.g., `https://your-app.streamlit.app`). Perfect for thesis demos — your panel can visit the URL on their phones.

Your dashboard will be live at a public URL. Share it with your thesis panel.
